## 한 줄 요약

## 코드로 확인한 한계 (2026-11-13 점검)
- **실제 영상 품질은 미검증.** SAM 2 추적은 합성 영상(노이즈 배경 위 단색 사각형)으로만 측정됐고, 40분 전체 실행도 한 번도 하지 않았다 [확인: README Limitations].
- **마스크 미리보기는 구현됨(2026-11-13).** View 메뉴에 두 가지가 있다. (1) 클릭 즉시 미리보기(P): 작업 프로세스를 `--preview-server` 모드로 띄워 SAM 2를 올려 두고, 현재 프레임의 클릭에 대한 마스크를 받아 표시한다. 실제 체크포인트로 '미리보기 마스크 = 작업이 그 프레임에서 만드는 마스크'(IoU > 0.95, 합성 영상)를 테스트로 확인했다. 클릭한 프레임만 보여 주며 이후 프레임의 추적 품질은 알려 주지 않는다. (2) 지난 실행의 마스크(K): 마스크 캐시에서 프레임별 마스크·탐지 박스·fail-closed 영역을 표시한다 [확인: `src/preview_server.py`, `src/app/mask_preview.py`, `src/mask_cache.py` `JobMasks`, `tests/test_mask_preview.py`]. 아직 없는 것: 브러시 수정, 패딩까지 반영한 최종 모자이크 영역 표시, 실제 영상에서의 확인. 패키징 빌드는 이 변경 뒤 다시 만들거나 검증하지 않았다 [미확인].
- **마스크 캐시는 구현됨(2026-11-13).** 청크마다 `masks_NNNNN.npz`(객체별 마스크, 탐지 박스, fail-closed 영역, 분석 단계 검수 이벤트)를 남기고, 렌더 전용 설정(형태, 강도, 패딩, 인코더 등 `RENDER_ONLY`)만 바뀌면 `--resume`이 SAM 2와 NudeNet 없이 캐시에서 다시 렌더한다 [확인: `src/pipeline.py`, `tests/test_mask_cache.py`]. 실제 4K 영상에서의 캐시 크기와 절약 시간은 재지 않았다 [미확인]. 캐시는 중간 청크를 보관할 때만 남는다(`--keep-temp`).
- **재클릭 비용.** 점이 바뀐 청크부터 영상 끝까지 전부 재계산한다 [확인: `prompt_signatures`].
- **청크 경계.** 경계마다 SAM 2 메모리가 초기화되고 마지막 마스크 하나로 재시드한다. 추적은 앞 방향으로만 간다 [확인: `src/tracking.py`].
- **NudeNet과 SAM 2는 연결돼 있지 않다.** 결과를 합집합으로 모자이크할 뿐, NudeNet 박스가 SAM 2 프롬프트나 재획득에 쓰이지 않는다 [확인].
- **객체별 모자이크 설정은 구현됨(2026-11-13).** 앱 Targets 패널에서 클릭한 객체마다 형태·강도(px)·패딩(px)을 따로 줄 수 있고, points 파일 버전 2의 `object_styles`에 저장된다(설정이 없으면 버전 1 그대로). 렌더는 (형태, 강도)별 레이어로 하고 겹치면 강한 쪽이 이긴다. 렌더 전용이라 바꾸면 마스크 캐시에서 다시 렌더한다 [확인: `src/points_io.py`, `src/mosaic.py` `apply_layers`, `tests/test_object_styles.py`]. 아직 없는 것: NudeNet 클래스별 설정(탐지 박스는 전부 작업 설정), 시간 구간별 설정, Feather, 강도 1~10 단계, 브러시 수정. 작업 전체 강도는 설정 창의 자동값(긴 변의 약 1/60)·슬라이더·미리보기가 있다 [확인: `a6444e1`].
- **NudeNet 실행 환경.** `models/`에 640 모델 파일이 없다(패키지 내장 `320n.onnx`만 있음). 설치된 onnxruntime 1.31.0은 CPU 전용이고, `censor_video.py`는 `providers`를 탐지기에 넘기지 않아 `onnxruntime-gpu`를 설치해도 코드 수정 없이는 CPU로 돈다 [확인].
- 앱은 작업 프로세스에 `--config`를 넘기지 않는다. `config.example.json`의 값은 명령줄 실행에만 적용된다 [확인: `src/app/job_runner.py` `build_args`].

## 다음 작업 (제안, 우선순위 순 — 1번 외에는 사용자 승인 전)
1. **실제 영상 1~2분 구간 테스트.** 어려운 장면(가려짐, 빠른 움직임, 화면 밖 재진입)이 든 구간을 중립적인 파일명으로 `input/`에 두고, 앱에서 클릭 후 fail-closed와 "Keep intermediate chunks"를 켜고 처리한다. 검수 로그와 눈으로 본 문제를 대조해 끊김의 위치와 종류를 분류한다. 이 결과로 2~4번의 순서를 정한다.
2. Feather, NudeNet 클래스별 설정, 시간 구간별 설정, 강도 1~10 단계(객체별 형태·강도·패딩은 구현됨).
3. 브러시 수정(수정 마스크를 `add_new_mask` 프롬프트로 재추적, 전후 비교 후 승인/되돌리기)과 수정 전후 마스크·오류 종류 기록. 마스크 미리보기는 구현됨.
4. NudeNet → SAM 2 제한적 연결: 놓친 대상 재획득, 새 대상 후보 제안(승인제). 합집합은 유지한다.
5. NudeNet 640 모델 다운로드, `onnxruntime-gpu`와 `providers` 연결 (패키지 설치는 사용자 승인 필요).
6. 앱에 NudeNet 탐지 클래스 선택 추가(현재 기본은 성기 2종만).
7. 패키징된 빌드 재생성 및 `tools/verify_build.py` 재검증(설정 창이 바뀌었음), 긴 영상에서의 패키징 빌드 검증.

## 지켜야 할 것
- 불확실한 프레임과 추적 실패를 조용히 통과시키지 않는다. fail-closed는 구현을 확인하고 적용한다.
- 원본 영상, 모델 가중치, 개인정보가 담긴 로그는 커밋하지 않는다. (`input/`, `output/`, `logs/`, `models/`, `samples/`는 `.gitignore` 대상)
- 검수 로그에는 영상 파일명과 경로가 들어 있다. 민감한 영상은 중립적인 파일명으로 다룬다.
- push, 원격 변경, 패키지 설치는 사용자 승인 후에만 한다.
- 테스트하지 않은 것을 완료로 보고하지 않는다.
