# samples

Test material created while developing the project. It is **synthetic** footage (no real people or content) and is not tracked by Git
(everything here except this file is ignored). `input/` and `output/` are left empty for your own videos.

| file | what it is |
|---|---|
| `synthetic.mp4` | 640x360, 30 fps, 160 frames, AAC audio. A magenta square moves across a noisy background; it is hidden for frames 70-85 (an occlusion that straddles the chunk boundary at frame 80 when `--chunk-size 40`) and leaves the frame at the right edge. A 12-bit frame-number code in the top-left corner lets tests check frame order. Generated by `tests/helpers.py: make_video`. |
| `synthetic.points.json` | One positive click on the square at frame 20, at (50, 180). Desktop-app sidecar name: it is auto-loaded when `synthetic.mp4` is opened next to it and the video fingerprint matches. |
| `points.json` | The same click, named for the command line (`--points samples/points.json`). |
| `synthetic_misplaced_click.json` | A click at (270, 180) on frame 20, which is background, not the square (left over from a test of the review screen). SAM 2 then segments the background blob, so this is a handy example of what a wrong click produces: a plausible-looking mask and few or no review flags. Not meant for the sample runs. |
| `synthetic_censored.mp4` | Result of a run with SAM 2 (small) and `--fail-closed`. |
| `test4k.mp4` | 3840x2160, 60 fps, 20 s (1,200 frames), AAC audio, ffmpeg `testsrc2` pattern. Used to measure streaming memory and speed. |
| `test4k_out.mp4` | Result of the NudeNet-only run on `test4k.mp4`. |
| `logs/synthetic_*` | Example review log (`_review.json`/`.csv`), detections, status and run log of the synthetic run. The JSON contains local file paths. |

Try it (from the project folder, with the virtual environment active):
```powershell
python app.py samples\synthetic.mp4
python censor_video.py samples\synthetic.mp4 --points samples\points.json --sam2-checkpoint models\sam2.1_hiera_small.pt --chunk-size 40 --analysis-width 320 --fail-closed -o output\synthetic_censored.mp4
```
Results on this clip (frames 20-69 IoU 0.91, recovery at frame 86 IoU 0.92) are documented in the README under "Tests"; they say nothing about real footage.
